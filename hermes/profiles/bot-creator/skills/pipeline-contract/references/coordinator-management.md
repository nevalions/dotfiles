# Canonical coordinator management

For every event or outcome handoff, load [outcome continuation](outcome-continuation.md): it owns the next-action record and turn-exit invariant. Before release load [whole-stage preflight](admission-preflight.md). This reference owns supported transport, identity and transition mechanics; do not duplicate the continuation procedure here.

Use the existing canonical Orchestrator Bot Chat, not a dispatcher worker, to handle native task event subscriptions. Preserve the configured model. Never strip worker/child identity or use HTTP/CLI to evade a denied tool. A management notification is not new production authority.

## Native board HTTP connection
The installed official Desktop protocol supports management via the running gateway without a standalone dashboard. Discover the existing Orchestrator endpoint with `discover_gateway_endpoint(profile_home)`. Require ready, exact profile identity and discovered loopback origin; never start a server as a side effect. The installed `hermes_cli.gateway_client._session_ticket(profile_home, endpoint, purpose='native-http')` implements the same-user Desktop bootstrap. The default OS principal must remain unchanged. Mint a fresh grant for EACH HTTP request and send it only as `X-Hermes-Gateway-Ticket`. No credential output/persistence, inherited proxies, redirects, Origin header, guessed token files or remote host. WebSocket interactive tickets are not native HTTP tickets. The underscore helper is version-sensitive: recheck installed protocol compatibility after upgrades, not silently substitute an auth bypass.

Exact native route: `/api/plugins/kanban/tasks/{task_id}?board={board}`. Validate/encode both identifiers, GET exact task and verify identity/state/assignee/dependencies and absence of active owner before any write. `PATCH` with explicit `{"status":"ready"}` or `{"status":"todo"}` can recover triage through the supported workflow transition. Keep ready for runnable tasks whose prerequisites/authority/budget are satisfied; otherwise use dependency waiting or leave parked. Read back the exact target after every mutation. A separate GET and PATCH is not atomic compare-and-swap; never race a claimed worker or treat the precheck as a lock. On ambiguous write error GET before deciding whether to retry. Preserve rejection/run history and the existing human decision gates.

## Coordinator deny-rule precision
Use executable-anchored approval globs, not leading-star substring chains such as `*gh*pr*create*` that match unrelated prose in task bodies. The installed matcher projects actual shell executable positions, including wrappers/compound commands; verify this behavior after upgrades. Test the exact legitimate board-edit command plus real publication/production command shapes in the dry-run classifier before deployment. Preserve unrelated safety rules. Classifier PASS is not end-to-end unattended execution proof or a sandbox. If a rule you introduced causes a false positive, correct it through supported configuration and rerun positive/negative controls before explicitly authorizing the affected management operation; do not evade the denial by rephrasing the command.

## Admission race warning
An unassigned READY card is NOT inert: the dispatcher can assign `kanban.default_assignee` and start a worker. Never use null assignee as a pause or a race-free bridge to review. Prepare an explicit intended assignee, complete body/artifacts/subscriptions and budgets BEFORE promotion; regard promotion as actual execution admission. For a coordination canary, use the normal intended author-worker -> native reviewer chain instead of assuming a non-worker can author/review an unclaimed ready card. Check effective dispatcher defaults during test setup without changing global defaults. Preserve and stop only exact accidentally admitted test owners, never unrelated workers. Failure of a canary design is not evidence the production workflow works.

## Recovery decision

The routine continuation default — the shared decision table and its limits — lives in the skill root (`## Routine continuation default`); apply it to any recurring blocker during authorized work instead of re-deriving rules here. Coordinator-specific additions only: prefer supported `hermes -p PROFILE config get KEY` over importing third-party parsers for configuration checks, and give a missing import or malformed ordinary command one diagnosed, in-scope correction within the same budget — never dependency installation or a model switch. Routine evidence-changing recovery inside standing scope (public source retrieval, local task artifacts/tests, verified missing-input delivery, bounded board routing) proceeds without user contact only after verifying old execution idle and remaining cumulative budget, and it must record the concrete changed evidence, the correction allowance consumed and the next expected outcome. Actual guard/auth denials still stop; required evidence cannot be skipped or fabricated; first-publication policy, production exec/mutation, credentials/secrets, destructive action and genuine user policy decisions remain explicit authority boundaries. The native management connection authenticates the coordinator; it does not grant those actions.

## Activation and verification sequence
1. Inspect the actual coordinator's non-worker tools, profile instructions, model and authenticated management connection. Use supported configuration queries instead of optional parser imports. Verify exact board selection with a read-only request before mutation.
2. Inspect the intended author/reviewer tool paths and conflicting instructions. Use native read_file/search_files for inspection, ordinary checksum commands for hashes and established bounded test entrypoints for tests. Do not wrap ordinary reads in arbitrary code execution merely to batch them: unattended approval can deny the wrapper before any read occurs. A denial followed by packaging the operation as a script or switching tools is not a clean pass; retain it and obtain a diagnosed authorized correction instead of treating it as equivalent execution.
3. Prepare the explicit assignee, owned workspace, scope, prerequisites, runtime, retry bounds and same-card review handoff while parked. A combined assignee/status PATCH is not necessarily transactional; inspect installed semantics, preserve a preassigned role and never claim CAS from separate checks.
4. Subscribe the exact substantive card to the canonical chat/profile/board with native wake events and read back that exact subscription. Historical subscriptions do not prove coverage of newly created or parent-created cards. Subscription creation does not replay an earlier blocked event; when adopting existing work, record and send one explicit handoff through a supported channel without pretending that manual kick was automatic.
5. Run the primary complete-input acceptance chain only after separate bounded live-test authorization, with all mandatory current-stage inputs verified before release under [whole-stage preflight](admission-preflight.md). Use an owned synthetic local fixture to isolate coordination from web-provider availability; prepare author inputs, reviewer selector, local delivery-preparation inputs, expected evidence and finite cumulative author/reviewer/coordinator budget while parked. Never admit the primary chain with a missing mandatory input. Observe the intended author executing the task, then the actual independent reviewer inspecting the exact candidate and closing the same-card review, then the native completion wake of the canonical coordinator, then its actual next authorized action: execute concrete local delivery preparation and retain its artifact/transition readback. Finally require a visible external approval gate: present the exact synthetic executor/target/candidate digest/commands/bounds/expected evidence/rollback packet to the user through a supported channel and retain delivery evidence; a pending or unverified presentation is not acceptance. Never execute the synthetic external-risk phase. Require no corrective parent DMs or manual releases after initial intake; any such intervention makes that segment assisted, not autonomous. A comment saying local work is accepted, downstream admission without observed action, suppressed final wake, or task Done alone cannot prove outcome continuation.
6. Retain exact event/run/session IDs and actual artifact/transition results in task evidence. Count every admitted model turn, including failed setup turns and manual corrections. Preflight configuration/tool mistakes before spending another model admission. Stop at the test budget rather than repeatedly redefining a final canary. Report each verified link separately; do not turn a failed review into an autonomy success.

## Separate bounded fault-injection scenario
Missing-input recovery is not primary-chain acceptance. Keep it offline-only unless separately authorized as a post-admission fault in an isolated synthetic task whose mandatory inputs were complete and verified at admission. Before injection, record the exact disposable fixture, one injected fault, recovery owner, expected stop/recovery evidence, rollback and finite cumulative budget (including all failed turns and corrections). Do not remove a mandatory input to manufacture an incomplete admission. Permit at most one bounded recovery within that authorization; stop on a real denial, unchanged blocker or exhausted budget. Retain results separately from the primary chain, disclose any parent assistance, and never execute an external-risk phase or reset the primary canary budget.

For a bounded ordinary-command recovery test, prepare and successfully verify an immutable input first, then inject one explicitly authorized command-selection error referring to an absent sibling path. Retain the actual nonzero result, correct the command once to the supplied valid input, and verify exit zero, output and unchanged digest within the original budget. A real guard denial stops the test rather than counting as its intended ordinary error. Label parent-specified setup separately from corrective parent intervention; this proves only the tested recovery, not native notification replay or timeout recovery.

Require a supported replay facility before live duplicate-notification testing. If none is established, report that branch untested; do not fabricate events by editing queues/databases, resubscribing or forcing task transitions. A user DM carrying old facts tests assisted reconciliation, not native replay. Similarly, do not manufacture ambiguous external writes by dropping responses. Keep happy-path, ordinary recovery, duplicate handling and ambiguous-effect coverage as separate results. Verify a final gate's actual history message or user-visible receipt on a legitimate subsequent read; do not claim a response exists before it is sent.

Coalesce inspection of related events and do not spawn a worker merely for routing. Completion is not proof of downstream acceptance. Missing transport or guard refusal is a concrete capability blocker, not justification for Hermes core patches.
