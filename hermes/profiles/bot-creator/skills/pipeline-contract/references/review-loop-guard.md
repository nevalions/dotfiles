# Outcome-first review-loop guard (all Kanban workflows)

This maintained shared policy applies to bugfixes, features, deployment preparation and other tasks, not one incident. Orchestrator owns its invocation and decisions. It is **procedural policy plus an offline evaluator**, not automatic dispatcher enforcement, an approval authenticator or a sandbox. Existing independent review, candidate, publication, production and cleanup gates remain mandatory. Models remain unchanged.

## Operational rules

1. Choose the shortest authorized critical path to the user's actual acceptance. Measure hypotheses eliminated, a causal candidate changed, discriminating test results and actual acceptance evidence—not cards completed, tool activity or supporting documents. At no progress, Orchestrator chooses one minimal discriminating experiment or a supported fix; do not create another chain of supporting tasks. Optional logging, observability, infrastructure, research and planning stages stay off the critical path unless a concrete necessity is demonstrated. Preserve parked work; do not restart it to justify sunk cost.
2. Reuse exact artifacts, reviewed diffs, failed-run provenance and evidence references. Send only relevant deltas and unresolved criteria, not repeated full context or full planning. Do not repeatedly validate unchanged immutable evidence; cache validation by exact digest and schema/policy version. Recheck freshness-sensitive facts (candidate changes, authority/revocation, live worker state, target state, provider budget) at the action boundary. Changed content invalidates affected review/test evidence. During iteration run the smallest discriminating test subset; at a candidate/review boundary run **all required gates**, never substitute the subset for final tests.
3. At admission, explicitly record role/task-sized total stage wall time (author **plus reviewer**, including queue/idle gaps), cycle wall time, checkpoint interval/wrap-up reserve, required tests, and applicable tool/token/provider-window budgets. No universal runtime copied from another role. Default rejection ceiling is **two per explicitly authorized cycle**; any override is explicit task policy. `no_progress_limit` is an explicit task value (minimum two comparable checkpoints); stage wall budget is mandatory. Cycle wall budget defaults to the same finite stage cap if not separately specified. Tool/token ceilings are optional only when unavailable or intentionally unconfigured with a reason; unknown usage is never zero or free quota. Keep actual nonoverlapping usage deltas, including reviewer, or UNKNOWN. Account/window percentages are separate signals, not task tokens/cost/attribution. Checkpoint before an expensive phase and assess remaining task/provider budgets. Never wait for reset and automatically retry to consume fresh quota; no model substitution.
4. Evaluate before dispatch/redispatch, at material checkpoints, before expensive phases and before each reviewer terminal transition. Default two rejections => ESCALATE. Same stable high/critical issue after one author correction => ARCHITECTURE_REVIEW, not another patch for the latest example. Identical evidence **and** unchanged diff across the configured comparable checkpoints => NO_PROGRESS. A denied command/capability mismatch escalates immediately; don't retry or bypass via shell/API/DB. Missing/failed/stale required tests blocks handoff. Elapsed, known usage ceiling, exhausted correction allowance or explicit stop => STOP. Every result routes to Orchestrator. CONTINUE means only this guard permits consideration, never approval or permission to publish/deploy.
5. ESCALATE/STOP: preserve source, candidate and history; park source against redispatch using supported parent actions and verify readback. Separately verify the exact worker idle. Never turn a rejection into approval or mark a routing card as outcome completion. A task-body instruction cannot close the native handoff/dispatch race. If worker management lacks edit/unlink/unblock, name the exact missing action and designated supported parent/operator; don't spin another coordinator. A triage/orphan outcome may not be accepted by unblock/promote: retain its identity and diagnose supported recovery separately. No direct DB status edits or fabricated approval.

## Offline evaluator and evidence interface

Run from this skill directory:

```
python scripts/review_loop_guard.py /absolute/sanitized-evidence.json
python -m unittest discover -s scripts -p 'test_*.py' -v
```

Exit 0 = CONTINUE; 2 = ESCALATE; 3 = STOP. Output includes fixed reason codes, `park_source`, `route=Orchestrator`, `review_approved=false`, `native_enforcement=false` and usage. Invalid inputs fail closed without echoing them. Use ordinary Python (optimized `-O` is rejected). Tests' `fixture()` is executable **synthetic schema documentation**, not authorization. To replay separately retained real evidence, set `REVIEW_GUARD_REAL_FIXTURE` to its sanitized input path; without it that one test is explicitly skipped. Do not copy incident IDs or transient provider metrics into durable policy.

Required top-level fields: `task`, exact absolute `candidate`, exact `scope` (prefer scope digest), `models={author,reviewer}` (exact model/provider identities from verified admission), original `stage_started_at`, `now` (integer epoch seconds), `history_complete=true`, `expected_records`, `stopped` boolean, `policy`, chronological `history`. Optional `next_action=author|review|handoff` defaults conservatively to author. Original stage start and full history do not reset with run/session/card replacement IDs. Adapter must independently verify history completeness/count against durable source and retain prior snapshots; this evaluator cannot discover withheld records or authenticate claims. Never feed raw task bodies, exception text or transcripts.

`policy`: nonempty `role`, positive `stage_wall_seconds`, optional positive `cycle_wall_seconds`, `review_rejection_limit` (default 2), `no_progress_limit>=2`, nonempty `required_tests` list; optional positive `total_tool_budget`, `total_token_budget`, and `provider_window_ceiling_percent` in (0,100]. Budget choice and rationale belong to task admission. `provider_window={reported_percent,source}` is optional selected-field evidence; record timestamp/window/timezone uncertainty separately. Before expensive work set `before_expensive_phase=true`, with independently verified `fresh_checkpoint`; absence escalates.

Each history record: contiguous `seq` starting 1, positive original `run_id`, `role=author|reviewer`, monotonic integer `at`, `outcome=checkpoint|correction|changes_requested|review_requested|approved|command_denied|capability_mismatch|blocked|stopped`. Author `correction` is a consumed correction attempt, including a failed attempt; emit before permitting another correction, not only on success. Multiple checkpoints per run are allowed; don't duplicate verdicts or usage. For progress comparison include both SHA-256 `diff_digest` (entire owned candidate identity) and `evidence_digest` (meaningful evidence, excluding timestamps/run IDs/heartbeat churn). Optional `issues=[{code: stable uppercase issue category, severity: low|medium|high|critical}]`; classify equivalent failures by root issue, not exception spelling or secret-bearing examples. Optional `tokens_delta`, `tools_delta`: nonnegative integers, null/absent means UNKNOWN; values must partition actual usage without double-counting. Reported total usage is null if any coverage is unknown; known subtotal is only a lower bound. Elapsed remains cumulative across both roles. Attach real evidence paths and eliminated hypotheses in the separate sanitized checkpoint packet, not arbitrarily changing evidence hashes to simulate progress.

At `review_requested`/`approved`, attach `tests={required-name: {status: PASS, exit_code: 0, diff_digest: exact-record-digest}}`. Missing evidence in a historical replay is UNKNOWN/missing, not proof tests failed; never synthesize PASS. The guard conservatively retains unresolved historic missing-test signals. Supply a separately reviewed corrected evidence packet with truthful source references if extraction omitted real results; do not rewrite original snapshots. Independent reviewer still verifies full test output and candidate content through the ordinary pipeline contract.

Use the [bounded implementer/reviewer handoff body](../templates/bounded-review-handoff.md) with exact task bindings and actual evidence; unresolved bindings stay NOT ADMITTED.

## Normal implementation admission and expired-budget amendments

Normal implementation admission explicitly sizes initial author + initial independent review + one correctable correction + independent rereview within a finite total elapsed cap, including queue/idle and coordination consumption. Choose and record task-sized numbers before release; do not promise a correction when its budget is unavailable. Keep the default two-rejection ceiling and all global limits unchanged.

Route existing schema, not invented evaluator flags: the default `review_rejection_limit=2` permits consideration after the first correctable rejection; explicit no-retry/no-correction at admission uses `review_rejection_limit=1` so the pending first rejection blocks author return. A later explicit stop uses `stopped=true` and retained stop evidence; a hard no-admission instruction also blocks procedurally before dispatch. Do not confuse native max_retries with this ceiling. Record each consumed author correction and use `next_action=review` for its independent rereview. Second rejection, same severe recurrence, denial and exhausted allowances still prevail. Unknown required budget usage blocks admission at preflight even where the offline evaluator only reports UNKNOWN; unconfigured optional ceilings need a recorded rationale, never invented zero usage.

An expired original allowance stays exhausted. A recovery approval is not an evaluator waiver: its old expired snapshot remains STOP. Only genuine explicit authority for a separately bounded amendment permits Orchestrator to record an additional finite allowance/deadline and admission counts, while retaining the original stage_started_at, all source/replacement records, old policy snapshot, old STOP result and cumulative consumed usage. Record amendment authority, scope, reason, original limits, added allowance, exact cumulative ceiling and deadline; include elapsed waiting since original admission rather than pretending the old elapsed fits. Never amend a global limit, clear stop history, hide unknown usage or enlarge unrelated scope. If required limits cannot be truthfully represented or remaining capacity verified, keep parked.

For evaluation of an authorized amendment, retain full history/original start and supply the explicitly amended task policy's cumulative finite stage cap (and any explicitly amended task-local cycle/admission bounds), never a fresh start. Preserve unamended tool/token/provider limits. If a manual `decision` is needed for prior escalation, bind it to that exact amended policy and full prefix using the existing schema below; the decision alone does not waive stage/tool/token exhaustion or stops. Keep both old and amended results and amendment consumption linked. One author correction and one independent rereview is a bound, not a new unlimited cycle; a new rejection ends this scoped recovery. No implicit amendment from a replacement-card ID or a generic workflow fix.

## Explicit manual escalation decision

Before any manual release, Orchestrator checks the decision against retained release history; changed snapshots/run IDs must not recycle an exhausted decision. Preserve independent failing probes for later authorized correction. Require a genuinely new finite decision and final independent review. This is caller-enforced evidence handling, not a request to implement native adapters or transactions.

No automatic new cycle, new model, new run or history reset. Orchestrator first verifies actual user scope/authority and unchanged models, parks the source, inspects evidence, then records architecture correction or minimal causal action. Supply optional `decision` with:

- `actor=Orchestrator`, actual `authorization_ref`, and `design_ref` to the recorded new decision (never falsely reuse old design approval).
- exact `binding` copy of `task,candidate,scope,models,stage_started_at,policy`;
- `after_seq` and `history_digest` from `history_digest(history[:after_seq])`, retaining all earlier records;
- positive finite `remaining_corrections` (typically one justified correction, explicitly chosen, not an unlimited retry); `acknowledged_reasons` exactly equal prefix signals. A missing-test signal cannot be waived by acknowledgement.

The decision permits only acknowledged prior escalation signals. New high-severity recurrence/denial/no-progress still escalates; fresh cycle rejection counting starts only at this explicit bound decision. Stage wall/tool/token budgets and explicit stops are not waived. At allowance exhaustion author dispatch stops; the final independent review may still run within budget. The evaluator does not clear explicit stop. Any human-authorized release is a separate supported parent action with verified worker idle/readback and retained stop/decision history; a new run ID is never release evidence. Authentication, integrity of the supplied binding, model identities, capability resolution and architecture quality remain caller responsibilities, not verified by a string field.

## Owner-authorized corrective phase (candidate interface)

An independently reviewed policy repair may use the existing evaluator's **separate corrective phase**, not a missing-test waiver or a higher rejection ceiling. Ordinary evaluation and the existing manual decision rules are unchanged. This phase is one author correction plus independent review within a separately owner-authorized finite `max_phase_seconds` cap, never more than 3900 seconds (including idle/queue/review/coordination); absent that field, the legacy 480-second ceiling remains unchanged. No automatic extension. The first new rejection stops this phase. Historical missing tests stay non-PASS, old stops remain stops, and an old ESCALATE result is retained verbatim under a historical STOP disposition: that annotation means the old work cannot resume, not that its original result was rewritten.

The canonical owner, never the author, retains the original sanitized guard packet and supplies a new `recovery_phase` object alongside its otherwise byte-equivalent parsed fields. The phase uses the ordinary evidence schema with its own complete contiguous history starting at 1, original task/candidate path/scope/models, new explicit start and finite policy, `review_rejection_limit=1`, unchanged required-test names and unchanged configured tool/token/provider ceilings. Add `authorization_ref`, `candidate_digest` (current whole-candidate digest), and `initial_candidate_digest` (the authorized starting digest; may be omitted only while unchanged). Phase records add actual `profile`; author/reviewer identities must match the independent profiles selected by the owner. Record the one consumed `correction` before author return becomes possible; after it, author redispatch is forbidden. The same admitted author may finish that bounded correction before its review handoff; this is not permission for another dispatch.

Supply authority separately: `evaluate(packet, recovery_authority=owner_record)`, or `python scripts/review_loop_guard.py packet.json owner-authority.json`. Embedded approval flags are not authority. The owner record requires:
- `actor=Orchestrator`, `actor_kind=human-authorized-owner`, `action=corrective-author-phase`, `decision=APPROVED`, `revoked=false`, exact authentic `authorization_ref` matching the phase; nonempty `reason` tied to retained findings, `acknowledged_reasons` exactly matching the historical replay's reasons.
- `historical_digest=history_digest(original_packet)` binding the entire original packet, including immutable original policy, timestamps, stops and full history, not only a trimmed prefix. Do not mutate or reinterpret historical outcomes to fit this mechanism.
- `binding` exactly copying phase `task,candidate,scope,models,stage_started_at,policy`; `candidate_digest` binding its initial candidate; `issued_at` equal phase start and not before historical snapshot time; `expires_at` strictly after the current phase time. Optional explicit `max_phase_seconds` must be an integer (not boolean or floating point), positive and <=3900; omission preserves the legacy 480-second bound, not a wider default. Require `expires_at-issued_at <= max_phase_seconds` (or 480 when omitted), and `stage_wall_seconds <= max_phase_seconds` and <= the expiry interval. The owner chooses the authorized total matching phase policy; 3900 can represent author 1800 + independent reviewer 1800 + coordination 300, not extra per-role time or another correction.
- A larger budget requires a fresh, separately owner-authorized record before admission, with exact new binding and authentic authorization reference. Never edit an already issued record's `issued_at`/`expires_at`, extend a running/expired phase, or rewrite current/old history to fit. Keep prior authority, policy, elapsed consumption and results immutable; this field repairs budget representation, not authority, rejection policy or ordinary retry limits.
- Distinct actual `author_profile` and `reviewer_profile`. Owner verifies the real native reviewer profile/run, not merely the supplied strings.

CONTINUE initially permits only consideration of corrective AUTHOR admission, never approval. Before review, require a new phase `review_requested` with all required PASS/exit0 tests bound to the exact current corrected candidate. Final handoff also requires later independent `approved`, different author/reviewer run IDs, matching profiles and fresh full test bindings. `review_approved` always remains false: `phase_ready_for_acceptance` is evidence readiness, not native approval or delivery permission. Historical missing tests are not supplied by these new results. New denials, missing tests, stop, budget exhaustion or rejection still block. Configured tool/token consumption includes both histories; unknown configured consumption fails closed. Optional unconfigured usage remains UNKNOWN, not zero.

**Trust boundary:** these are offline schema checks and cooperating-owner instructions, not authentication, filesystem immutability, an atomic dispatch guard or a sandbox. A hash only binds supplied evidence; it cannot discover withheld history, prove a user message, verify current candidate bytes, time, run/profile identity, reason adequacy or revocation. The owner must independently authenticate the exact approval and current authority at release, verify baseline/candidate hashes and full durable history, enforce the actual deadline with supported native limits/scoped stop, keep owner records out of author edit scope, and retain original snapshots/results. An author cannot issue/amend this record or coordinator history. No new card, live release, skill activation, model/config/permission change or production action is implied by this interface.

## Existing author/reviewer protocol — no runtime changes

Do not patch Hermes core/runtime or require native integration, core tests, a poller or a new specialist. `max_retries` is a failure breaker, not a review-rejection cap. The native request_changes transition returns work to the author; invoking it and blocking afterward can race dispatch.

1. Both existing author and reviewer load this reference before continuation/terminal handoff. Read full retained source runs, comments and earlier linked attempts, preserving original stage start and rejection count. Missing history => block for exact evidence, never assume zero.
2. Reviewer evaluates **including the pending rejection**. First correctable rejection may use native request_changes only when the guard permits it. At the second rejection, or earlier recurrence of the same high/critical root issue after correction, **do not invoke request_changes**. Record severity, stable issue code, exact candidate, evidence paths, prior verdicts and proposed minimal decision in the supported native block reason. Use `kanban_block` with the actual injected schema; a human-held `needs_input` block is appropriate for exhausted correction/design allowance, not dependency waiting. No approval is implied.
3. Notify the existing outcome owner before terminal block via an allowed native comment/established parent handoff; reviewer profiles without messaging must not invent a DM API or shell out. The parent can append the handoff on the existing owner using `hermes kanban --board <board> comment <owner> --author <actor> <evidence-and-decision>`. CLI parent block: `hermes kanban --board <board> block <source> --kind needs_input <reason>`. Verify exact source/owner readbacks; block recurrence can route to triage, which must stay parked. Stop after the terminal transition.
4. Author independently checks history before any continuation even if dispatched: exhausted/recurrent finding => native block and owner handoff, no correction. Orchestrator retains source and failed probes, checks exact worker idle, chooses a bounded causal/design decision, and obtains only genuinely new authority. No automatic reset or new model. Parent performs only missing supported management operations.

This prevents a cooperating reviewer from requesting another author run; it is **procedural enforcement, not atomic native enforcement**. Symlink/config checks prove availability/instructions, not that a live model obeyed. Existing source-state constraints remain: unblock is blocked/scheduled; promote is todo/blocked, not triage. Inspect installed behavior before recovery and never mutate the DB.
