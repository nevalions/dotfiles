# Bounded research and diagnostic admission

## Phase contract
Apply [standing public-source retrieval](public-source-retrieval.md) for missing public documentation/source. In-scope bounded unauthenticated retrieval is routine evidence collection, not a new human gate; installation, execution, private access and production traffic remain separately controlled. Respect explicit offline assignments and tool denials, and charge retrieval/inspection to the existing stage budget.
Size research/diagnostic runtime and calls by the actual stage, repository breadth and required evidence under one user task scope. For unscoped research only, the fallback is a 5-minute triage (300 seconds, at most 12 tool invocations including batched subcalls, never conceal calls in loops). Reuse existing findings, reports, source ledgers and native comments; inspect only missing or stale evidence, not the whole investigation again. For that fallback triage, split context/gap identification (60 seconds, 3 calls), discriminating evidence (180 seconds, 6 calls), and report/native handoff (60 seconds, 3 calls); explicit task-sized budgets use their own stage allocation. These are ceilings, not quotas. Stop early when the decision is supported. Save evidence before the next expensive call, including source locator, observed result, eliminated alternative, remaining uncertainty and next discriminating test.

A deeper diagnostic is a phase of the outcome-owned task, not necessarily a new card or human decision. Its fallback budget is 600 seconds/20 calls; explicitly scoped work may use a larger justified finite admission budget with at least 60 seconds reserved for handoff. Record the existing user scope reference and question being tested; no new approval is needed for in-scope selected-field safe reads. Continue subsequent pre-admitted phases automatically, but never extend an exhausted attempt, repeat an unchanged blocker, or redispatch after timeout without a diagnosed cause and bounded Orchestrator correction. Preserve partial findings first. Stop at the first of budget/call ceiling, supported decision, alternatives discriminated, repeated unchanged failure, missing capability, or exhausted authorized attempts. An honest unknown is a valid research result; do not keep probing until certainty.

Researcher owns evidence synthesis, not broad production execution. Route necessary production diagnostics to an explicitly authorized executor with the exact command list, per-command timeout at most 60 seconds, at most 3 commands per test and 2 attempts. Commands must fit the remaining phase time minus the handoff reserve; use a shorter timeout if necessary. Larger tests need a new scoped approval, not silent limit changes. No production test is authorized by this document alone.

## Observable checkpoints and lifecycle
Post a native task comment at start: scope, reused evidence, bounded phase/call budget, next decision and owner. Post another on meaningful phase transition and before expensive calls/waits if the evidence or decision changed. At tool-return boundaries, if roughly 120 seconds have elapsed since the last comment, publish current findings or explicitly state no new evidence and the blocker. Coalesce coincident checkpoints; no heartbeat spam and no fake promise of timed notifications while a call is in flight. A private scratch file alone is not user-visible progress. Keep detailed evidence in a durable task-local report and link it in the comment.

Begin wrap-up before the final 60 seconds. Submit findings through injected native lifecycle tools for review/completion when the bounded research deliverable is ready, even if the underlying incident remains unresolved. Use native block/needs-input when an external capability, missing approval, credential or required input prevents the deliverable; name the unblock owner and exact requirement. Do not label useful partial findings a failure solely because root cause remains unknown. Verify the actual terminal handoff/status, not just a comment. Never leave an idle running owner as permanent incident tracking.

If decomposition requires an intake card to finish, label it `intake/delegation done`, never `incident resolved`. Retain a distinct final-acceptance card with the original user criteria and explicit owner. Link remediation, delivery and production-validation evidence separately. Final acceptance stays unresolved until all original criteria are verified; decomposing or reviewing research is not incident closure. These are future admission rules, not permission to mutate existing live cards.

## Supported runtime controls and caveats
Verified against installed Hermes source and bundled official documentation (`website/docs/user-guide/configuration.md`, Wall-Clock Run Budget):

- Kanban creation tool schema accepts integer `max_runtime_seconds`; CLI `hermes kanban create TITLE --max-runtime 5m` (or `10m`) maps to that stored field. Read back the exact created task and active attempt. A task-body deadline or null field does not enforce anything.
- CLI creation accepts `--max-retries 1`, meaning trip on the FIRST failure, not one retry. DB API accepts `max_retries=1`. The installed creation tool schema/handler does NOT expose that field; do not invent a tool parameter. Use an authorized supported CLI creation path that sets both fields, otherwise block admission until the retry policy can be verified. Do not edit live SQLite to retrofit limits.
- `hermes_cli/kanban_db_dispatch.py:enforce_max_runtime` checks per-attempt elapsed time on dispatcher ticks, SIGTERMs and then SIGKILLs after a grace period, and records timeout. Without the first-failure breaker it requeues. This is not an exact-second deadline: dispatcher availability, host-local claim ownership, worker PID identity and owner-reclaim protections matter. An unverified live PID is deliberately not killed. Verify the enforcement path in isolation; do not promise every running card will be forcibly stopped.
- `agent.run_budget_seconds` and CLI `hermes chat --run-budget N` are cooperative per-conversation-turn controls, NOT a process wall-clock kill switch and NOT a Kanban task-creation parameter. They trigger a one-time wrap-up notice at 80% and cap implicit provider stale timeouts at `min(original_timeout, max(60, remaining * 0.5))`. Explicit provider/environment stale-timeout overrides win; long active tools/calls can overrun, and the clock resets each turn. These controls do not replace the Kanban cap or command timeouts. Do not change profile/global configuration or models to install this policy.

Source anchors: `tools/kanban_tools_schemas.py` and `tools/kanban_tools.py` (creation); `hermes_cli/kanban_parser.py` / `kanban.py` (CLI fields); `hermes_cli/kanban_db_dispatch.py` (timeout/breaker); `agent/conversation_loop.py` (wrap-up); `agent/chat_completion_helpers.py:cap_to_run_budget` (provider timeout). Recheck installed support before future admission; configuration presence alone is not enforcement proof.

## Offline admission helper
Run `python scripts/validate_gate.py evidence.json research` before dispatch, separate from development stages. `research` evidence contains: `phase` (`triage`/`diagnostic`), `budget_seconds`, matching `max_runtime_seconds`, `max_retries: 1`, `tool_call_limit`, `update_interval_seconds` (at most 120), `wrapup_reserve_seconds` (at least 60 and less than budget), nonempty `runtime_evidence_ref`, `checkpoint_ref`, `prior_evidence_ref` (explicit no-prior-evidence check is acceptable), `stop_criteria`, `owner`, `final_acceptance_card`, `auto_extend: false`, and boolean `production_execution`. Diagnostic also requires `authorization_ref`, which may reference the existing user task scope for in-scope safe discovery rather than a new per-read approval. Optional `budget_limits: {seconds: positive integer, calls: positive integer, scope_ref: nonempty string, rationale: nonempty string}` replaces the fallback time/call ceilings only. Caller must verify that scope actually covers this finite stage and its proposed bounds; the JSON is not authorization. Production execution still requires separately authenticated exact execution authority, a non-researcher owner, `commands_ref`, `command_timeout_seconds`, `commands_per_test`, `max_attempts` within the ceilings above; task-sized budgets never relax those experiment limits. See `scripts/test_research_budget.py` for a synthetic fixture.

The helper rejects malformed/unbounded declarations. It does not authenticate authorization, count live calls, schedule comments, create cards, or enforce deadlines; caller verifies truth and exact readback. Offline fixtures are not live enforcement evidence. Models, tools, native review and existing delivery/cleanup invariants remain unchanged.
