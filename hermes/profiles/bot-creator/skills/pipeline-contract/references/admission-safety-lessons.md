## Mandatory unattended local verification

Before dispatch or recovery from a command denial, load [local verification admission policy](local-verification-policy.md). Routine authorized local tests need a supported, preflighted execution interface—not repeated human permission. Preserve actual denials and external-risk gates; only an explicit reviewed interface decision permits a replacement procedure. Never enable blanket unattended approval or disguise a denied command.

## Mandatory independent reviewer binding

Before author admission and after review handoff, follow [explicit independent-review routing](explicit-reviewer-binding.md). Verify the actual native reviewer selector and actual worker profile; prose requesting review is not configured routing, and a new author session is not independent review. Routing repair within already-approved review scope is coordinator work, not a new human permission gate. Classify a verification-policy denial separately from a candidate defect: retain completed independent checks and candidate identity, leave the denied checks explicitly unverified, and recover only the missing reviewer work after the policy owner resolves the execution boundary. Do not restart the author or repeat the full implementation because a supplemental check was denied.

## Mandatory feasibility and local recovery

Before any admission or response to recurring triage, load [feasibility before admission](feasibility-before-admission.md). Check all critical inputs together; resolve missing inputs before releasing implementation. Orchestrator owns ordinary local methodological amendments within the user's original outcome and authority, including a clearly labelled prospective test when exact historical evidence is unavailable. Do not turn those choices into repeated human micro-approvals. Preserve real acceptance, independent review, finite cumulative budgets and external-risk gates. A runnable candidate—not another preparation report—is the next deliverable.
