# Whole-stage admission preflight

Coordinator completes one compact readiness table in the existing outcome comment/artifact BEFORE releasing the next substantive stage. This is a checklist, not a new runtime validator or approval service. Load [feasibility](feasibility-before-admission.md), [local verification policy](local-verification-policy.md), [reviewer binding](explicit-reviewer-binding.md), [review-loop guard](review-loop-guard.md), [admission lessons](admission-and-coordination-lessons.md) and the relevant [contract](contract.md). Unknown critical prerequisites fail closed; do not discover them serially through failed worker admissions.

| Requirement | Retained evidence and admission rule |
|---|---|
| Outcome/scope | Original real-world acceptance, next executable deliverable, authority reference and exclusions; explicit offline/no-correction/stop instructions. Local/public reads are standing work only within that scope. |
| All inputs | Inventory the entire critical set together: exact path, digest/provenance, compatibility and freshness. Obtain critical implementation inputs before release. Missing historical bytes remain UNKNOWN; a labelled prospective comparison is allowed only if original acceptance does not require exact forensic reproduction. Never synthesize historical equality. |
| Workspace/identity | Resolve ownership/symlinks and repo instructions/freshness; preserve dirty and parked work. BEFORE repo-edit admission bind the existing retained candidate with native dir and read back persisted kind/path against its exact candidate digest; missing/wrong binding is NOT ADMITTED. Workers cannot create a divergent authoritative candidate. Follow [workspace lifecycle](workspace-lifecycle.md); retained non-repo packet directories apply only to non-repo work. Record base/diff digest and intended assignee; do not create a dummy repository. |
| Tool and execution path | Enumerate required read/write/test/build/handoff operations in intended consumer context, actual schemas, admission mode/hooks and finite-turn guard. Inspect unfamiliar entrypoints/import effects. Host CLI, another profile, static classifier or policy text is insufficient. Preflight harmless representative required interfaces without spending unapproved model admissions; if unavailable, mark NOT VERIFIED and stop the dependent admission. An actual denial is not permission to test alternate syntax. |
| Reviewer | Actual native reviewer selector explicitly independent of author; owned candidate/test coverage and allowed review writes, remaining budget, supported handoff/recovery. After handoff inspect actual run profile/session. Preserve prior independent evidence and recover only missing checks for policy denial. |
| Coordination | Canonical non-worker board/chat/profile identity, authenticated supported connection and exact target board; required create/edit/dependency/adopt/release capabilities or disclosed designated parent action. Verify exact card subscription, idle owner, dependencies/source-state transition, explicit assignee and persisted runtime/retry settings while parked. No identity stripping, DB write or READY parking. |
| Budgets | Role-sized cumulative author+review/coordination wall time, active versus queued/manual wait, tool/admission limits when available, checkpoints, wrap-up reserve, stop/correction conditions and full rejection history. For normal implementation explicitly reserve initial author + first independent review + one correctable correction + independent rereview within the finite cumulative elapsed cap; this is not permission after explicit no-retry/no-correction, second rejection, severe recurrence, denial or unknown/exhausted budget. Route the existing evidence schema as specified in [review-loop guard](review-loop-guard.md). Preserve consumption; max_retries is a failure breaker, not lifetime attempt cap. Run review_loop_guard and applicable validate_gate before release. |
| Delivery feasibility | Check the downstream interface NOW: exact repository/branch/target, non-secret authentication capability, live protection and actual required CI contexts, candidate-specific PR-vs-push evidence, publication/build/auto-deploy triggers and intended executor. Distinguish OCI index from platform manifest and local stale config from remote state. Missing downstream external permission blocks that external phase, not otherwise feasible local work; record it as deferred gate with owner and concrete discovery/request action. Required stage inputs cannot be deferred this way. |
| Approval/acceptance | Prepare exact scoped packet only when runnable; commands, target, digest, executor, bounds/window, acceptance and rollback. Approval must precede ANY publication that can auto-deploy; a later production gate cannot protect an earlier push. First publication with no policy needs approval; no force push/check weakening. CI is exact final commit evidence, not production acceptance. Keep original application acceptance separate; user-reported recovery does not invent row/file checks. |
| Continuation | Existing outcome next-action entry, next trigger/responsible actor and real return evidence. Completed preparation cannot leave owner without supported continuation. Require action readback/run evidence before saying started. |

## Reuse and independent concurrency
Reuse immutable input/artifact/review/test evidence by exact candidate digest AND schema/policy version with source references. Revalidate only affected evidence when content changes; never re-run full discovery because a message timed out. Final required candidate gates remain mandatory. Recheck freshness-sensitive authority/revocation/window, worker idleness, target state/protection/CI, resource availability and budgets at the action boundary; a cached PASS does not freeze them.

Batch independent read-only prerequisites (input provenance, tool availability, reviewer binding, delivery metadata) in the same bounded inspection when permissions and tooling allow. Parallelize only genuinely independent checks with disjoint ownership, no shared writes, and authorized fan-out. Dependent reads, approval-then-execution, candidate mutation-then-review and native transitions remain ordered. Do not create workers/cards merely to parallelize trivial probes. Ordinary native file tools and single-purpose commands remain preferable to arbitrary batching wrappers that the intended guard cannot admit.

## Approval capability verification

1. Inspect `hermes -p ROLE approvals --help` and `approvals test --help`, then use supported nonexecuting `hermes -p ROLE approvals test --json -- COMMAND` for the exact planned operations across every affected role. Record effective inherited policy rather than treating absent configuration keys as disabled protection.
2. Check both routine-operation acceptance and dangerous-operation rejection. Keep destructive controls nonexecuting; an allowed classifier result is neither authorization nor proof that a test command is side-effect-free. Check the command structure and paths, not just the executable name.
3. Before proposing an approval remedy, verify the installed mechanism's semantics: pending-request creation, unattended behavior, compound-command matching, exact versus glob entries, profile scope and any actual working-directory restriction. Never promise a one-shot pregrant or exact-command allowlist from its name alone. A successful parent approval does not transfer to a child.
4. Separate classifier dry-run evidence from actual intended-worker execution. Establish the supported authorized interface before admitting a worker; do not spend another admission to rediscover the same blocker. After an actual denial, preserve it and obtain a real supported resolution, not alternate syntax, file reads or another identity that reproduces the denied operation.
5. Reuse verified capability results by effective role policy and relevant tool/runtime version. Retest affected operations after changes; do not widen all profiles because one command failed, or repair only Reviewer without checking other consumers of the same operation.

## Decision
Record each row as verified, missing, unknown or explicitly deferred-to-external-phase, with evidence path and existing owner. Release only if EVERY current-stage critical row is verified, actual independent review and continuation paths are ready, and relevant validators permit consideration. Resolve missing local prerequisites within standing scope and budget once; otherwise give the precise blocker/owner/resume condition. This table does not replace supported guards, independent review, user authority or live transition readback. No model, runtime, scheduler, database or production modification is authorized by preflight.
