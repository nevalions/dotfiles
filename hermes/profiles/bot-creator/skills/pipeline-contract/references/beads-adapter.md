# Explicit Beads CLI adapter

This is an explicitly selected supported CLI integration, not a silent fallback around a plugin refusal. The default-profile `hermes-beads` plugin has six tools (smoke/frontier/show/claim/update/comment), not create/close. Do not assume another profile has it. No plugin install or production tracker mutation is part of workflow installation.

Before actual authorized tracking, read `/home/linroot/.agents/skills/beads/SKILL.md`, pin `/home/linroot/.local/bin/bd` (observed 1.3.1; multiple PATH binaries exist), inspect current `--version`, `prime` and per-command help. Use explicit target checkout and `--actor 'hermes:beads-coordinator:<session-id-or-once-generated-uuid>' --json --sandbox` on every invocation; sandbox disables automatic Dolt push, not authorization checks. Preserve actor in task session state, not global shared config. Never impersonate previous actor.

Run pinned `bd --actor "$ACTOR" --json --sandbox where` in target checkout. If no store, skip tracker stage or block only if tracking is required; never init, import, override BEADS_DIR/database or synchronize to force discovery. Worktrees normally share main store.

For requested create: ask new vs existing if unspecified; `create --title ... --description ... --type task --priority ...` with explicitly chosen fields, dependencies and optional parent. Use current help: in 1.3.1 `blocked-by:ID` means new issue depends on ID; `blocks:ID` means the reverse. Create parents first. Read back returned explicit ID. Claim with `update ID --claim` only when authorized and unowned; then `show ID` confirms current session ownership. Do not bypass an existing owner's refusal through another interface.

For requested close: validate pipeline `close` evidence, `show ID`, compare actual owner to current actor, and require recorded authorized ownership handoff if sessions differ. If another actor owns it, stop for owner-mediated release/transfer; do not force, overwrite assignee, or adopt its actor. Then `close ID --reason 'verified delivery/result SHA and CI reference'` and `show ID` to confirm. Explicit ID always, no --force, --continue, --claim-next, blind retry or implicit last-touched selection. If tracker data changes tracked files, route authorized bookkeeping through Commiter and CI again on final resulting SHA. No `bd dolt push` without separate remote authorization.
