# Ansible project pipeline
One native `ansible` board under existing canonical non-worker Orchestrator; one `ansible-operator` owns host implementation AND explicitly authorized node execution outcomes. Cluster Operator remains Kubernetes/GitOps owner. Reuse Reviewer (strong independent Astra reviewer, verify actual configured model/run without changing it), Tester, Commiter, CI Watcher, Repo Docs and Wiki Skill. No extra bots, routing-only cards or per-project Delivery/Wiki boards.

Load maintained workflow-foundations, admission-preflight, contract, gate-and-workspace-procedure, workspace-lifecycle, review-loop-guard, local-verification-policy and explicit-reviewer-binding for corresponding phases. Operation contract and shared conflict root are in ansible-operations/references/operation-contract.md; mandatory for BOTH operators. Consumer skill access must be verified before release.

Minimal path: authentic intake + task-owned candidate → local implementation/safe tests → explicitly bound native independent Reviewer → required Tester/docs → shared Delivery when authorized → separately approved host execution on ansible board → observed operation acceptance → durable Wiki delta. Native reviewer binding and actual reviewer run/profile must differ from author; null reviewer is not a default. Reviewer inspects effective defaults, check-mode exceptions, imports/tests, private-map binding without disclosing mapping, command scope, recovery and concurrency. No self-fix/self-approval. Retain rejected findings; second rejection/recurring severe defect stops per maintained guard.

Local source Done remains Done after accepted code; original operational outcome stays pending. Use at most the needed substantive execution card when code and execution are separate stages, not a card for every gate. Code acceptance, publication/CI and actual node acceptance are separately evidenced. Execution success requires intended configuration/version/service state, node recovery, cluster/workload/storage/network health over approved soak and original user acceptance; exit zero or Ansible recap alone is insufficient.

Git/CI use maintained delivery-factory.md on shared `delivery`, existing Commiter/CI Watcher. That factory's Cluster Operator deployment row applies to Kubernetes only; Ansible host execution stays on `ansible`, not delegated to Kubernetes owner. Inspect earliest auto-deploy trigger and exact policy before offering a mode. Carry source provenance/immutable hashes in body/artifacts only. NEVER cross-board parent/dependency links or worker CLI/API escape. Canonical Orchestrator performs supported parent handoff and verifies target readback. Wiki uses wiki-factory.md on shared `wiki`, only concrete durable deltas, no duplicate cards. No source Done/queued docs claim may close operation acceptance.

Before admission: consumer tools/skills/model/auth, exact candidate, native reviewer binding, runtime/retry and cumulative stage budget, real authority/observations, shared conflict queue across both owners, subscriptions and accessible evidence. Initial live execution uses no automatic side-effect retry; reconcile ambiguous effects first, prove idle and remaining authority before any bounded recovery. Supported native max-retries breaker is not an exactly-once guarantee. No board is created by this package.
