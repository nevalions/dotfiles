# Shared Wiki factory — durable deltas, existing workers

Load at research findings, every review verdict (including rejection), final outcomes and required documentation closure. Extend outcome-continuation.md, coordinator-management.md, admission-preflight.md and review-loop-guard.md; do not replace their gates. One shared board: slug `wiki`, display `Wiki`, across all projects. Keep implementation/review on source boards and Delivery on `delivery`; no per-project Wiki boards.

## Owner, authority, authoring
Canonical non-worker Orchestrator evaluates stages, prepares small provenance packets, reconciles and admits. Substantive curation/authoring belongs to `wiki-skill` Kanban workers. Bot Chats clarify only; generic named-bot messaging or “handle simple requests” does not authorize untracked wiki work. Do not replace wiki-skill with coordinator-authored docs, runtime code, auto-doc scripts, a compiler, new bot or service.

Standing write authority is scoped local wiki paths only: no commit, push, publication, sync setup, deployment, credentials or unrelated edits absent explicit applicable policy. Check whether local writes trigger existing sync/publication; if so, require that effect's authority or use an approved non-publishing candidate. Resolve the canonical wiki root, repository instructions, symlinks and dirty ownership without reading secret files. Do not presume the default path is the effective consumer path. Load maintained `llm-wiki` and applicable `obsidian`/local schema instructions for orientation, authoring, index/log and validation conventions; this factory does not duplicate them. Search existing pages and index first; update matching pages before creating a new one. Preserve immutable raw sources and mass-update approval thresholds. Denial or conflicting scope => park, never bypass.

## Stage decisions, not obligatory cards
After reconciling latest source state, compare the packet and existing wiki coverage; dispatch only a concrete durable delta useful beyond this run. No mandatory card per stage. Keep one compact decision in the existing outcome entry, not a new routing card.

| Event | Durable delta when needed | Qualification |
|---|---|---|
| research | reusable findings, narrowed alternatives, documented constraints or unresolved questions | Separate observation, hypothesis and uncertainty; cite sources/dates, do not turn an untested idea into a procedure. |
| review | material acceptance conditions, defects, rejected approaches or reusable safety lessons | Record rejected, not accepted when verdict failed; preserve reviewer identity, exact candidate binding, retained rejection evidence and correction history. A rejection may be valuable knowledge without making the source deliverable acceptable. |
| final | actual verified result, changed operating facts/procedure, outstanding acceptance and required docs coverage | Separate prepared, installed, offline-tested, executed, accepted and user-confirmed. Never relabel staged instructions as active behavior. |

No delta / already covered unchanged digest => verified no-op: no new comment, task, wake or token-spending worker. An optional update may remain pending without blocking unrelated authorized source work. Required final documentation keeps the original outcome visibly `docs-required/pending` with Wiki task ID, owner, blocker and next trigger until verified coverage; report other completed work separately. A queued handoff is not docs closure; wiki Done is not source acceptance, independent review approval, delivery or original outcome completion.

## Immutable accessible handoff and identities
Retain packets outside scratch in existing outcome artifacts; copy necessary sanitized evidence or provide worker-readable immutable paths with SHA-256 hashes. Task body must cite source board/task/outcome/run/hash, author and reviewer provenance, actual verdict/history, stage, evidence level, exact durable delta and uncertainty, intended wiki root/paths, existing-page search evidence, required/optional docs coverage, authority/exclusions and cumulative budget. Include candidate/policy/packet digests, all source evidence references and prior Wiki receipts. Verify actual worker access before release. For Kanban-origin work, missing source run/hash or inaccessible evidence is a blocker, not an invented identifier. For genuinely non-Kanban work (such as user-authorized parent-operated configuration), declare `source_kind: parent-operated`, source board/task/run explicitly `N/A`, authentic initiating user-request/session attribution, responsible parent profile, retained operation/result artifact paths and their verified SHA-256 hashes. Missing authentic attribution or artifact hashes still blocks. This is an alternate provenance type, not permission to omit existing Kanban identities or fabricate a source card. The coordinator verifies attribution against accessible retained records before admission; a worker receives a sanitized immutable evidence packet, not private transcripts.

Use source IDs in body only, never as Wiki `--parent` or link IDs. No cross-board dependencies. Wiki workers never query or mutate another board or use CLI/API to evade their board fence. Only canonical authorized coordinator reads source boards and records verified backlinks. Same-board dependencies may use exact Wiki IDs but cannot replace fresh admission validation.

Stable logical job fields: schema version, source kind, source board and original outcome/task (for Kanban provenance), or authentic initiating-request reference plus responsible parent profile and retained outcome reference (for parent-operated provenance), canonical wiki root and topic/coverage scope. Stable action fields add ordered source board/task/run/content hashes for Kanban work, or ordered parent-operation artifact identities/content hashes for parent-operated work, plus stage/durable delta digest and scope/policy digest. Explicit N/A values never replace the required parent provenance fields. Encode fields as canonical JSON (sorted keys, compact separators, UTF-8, no NaN); SHA-256 identifies each record. Retain exact fields beside hashes; timestamps/event arrival alone are not identity. The same key with different payload => block. Use supported `--idempotency-key` for action creation, but reconcile existing outcome receipts plus ALL Wiki tasks, including archived and manual jobs without keys, by provenance, topic and affected paths first. Native non-archived dedup is not lifetime or side-effect dedup; missing history => block rather than assume absence.

Coalesce pending updates for the same logical job while parked and verified idle: retain previous packet versions, assemble one new immutable packet and revalidate changed packet (source, scope, verdict, paths, budget and affected review) before release. Never alter an active worker's input. Native idempotency keys are not known editable: keep the old card key as creation identity, record each new action identity and packet digest in its body/outcome history; reconcile both before any new create. An active job gets at most one pending delta in the existing outcome record for later reconciliation, not a parallel duplicate. Content or verdict change is not a no-op simply because topic/task matches.

## Shared ownership and admission
One coordinator-owned serial queue in existing outcome artifacts/comments. Conflict keys: canonical wiki root plus shared `index.md`, `log.md`, schema, and all overlapping wiki paths (resolve aliases/symlinks). Since normal writes share index/log, serialize normal writes for the entire root even for unrelated source projects. Check active, uncertain and manual editors across all jobs before release; owner unknown => park. Never overwrite unrelated dirty files or refresh a checkout under another worker. This is cooperative coordination, not a lock, lease, CAS or exactly-once guarantee. Refresh target hashes immediately before writing; drift => stop and reconcile.

Create only needed substantive cards BLOCKED, explicit assignee `wiki-skill`, retained `dir:/absolute/owned/path`, `--skill pipeline-contract` and `--skill llm-wiki`, native `--completion-contract local-only`. Require consumer skill loading and representative read/search/write/check/handoff tool preflight, not CLI configuration alone. Missing shared skill link requires owner-approved native link/config provisioning; do not mutate another profile's skills or SOUL as a workaround.

Bind required independent reviewer and review scope before admission. Review is independent of the wiki author and checks exact changed docs/evidence/paths and required conventions; verify actual reviewer run/profile, not self-review or a second wiki-skill session. Existing source review remains source evidence, not review of newly written wiki pages. If risk/policy permits no separate wiki review, record that scoped decision explicitly without claiming review; required review or unresolved qualifications keep closure pending. Preserve rejection limits and severe-recurrence stops.

Record finite total wall/admission/read bounds, consumed/remaining author+review+coordination budget, checkpoint and wrap-up reserve. Set finite `--max-runtime` and `--max-retries 1`; the breaker/runtime requeue is not a lifetime budget. Default bounded small update proposal: 15-minute total active wall allocation (author 7m, reviewer 5m, coordinator 3m), at most one initial author and one independent reviewer admission plus one evidence-changing recovery within remaining allocation, at most 12 reconciliation reads and last minute reserved for handoff. Size differently only with a recorded scope/budget decision; unknown usage is not zero. No new-card budget reset.

Subscribe both relevant source cards and the Wiki card to exact canonical Orchestrator board/chat/profile with `notify+wake` or `wake` before release; verify exact subscriptions and current event state (subscriptions do not replay old events). After preflight, admit once and read actual run separately from READY. Native wake must produce bounded reconciliation and next action or visible gate, not self-wake loops or polling services. Existing cards adopted after events need one disclosed supported handoff.

## Result, failures and closure

Prefer the ordinary native file tools for scoped wiki authoring; optional interpreter/batching conveniences are not prerequisites to writing documentation. If a wrapper is denied, report the exact denied interface and whether any inner operations ran rather than describing a blanket write prohibition. Stop and obtain an explicit reviewed interface disposition before a bounded continuation; do not disguise the denied payload or relax approval policy. Preserve the same task, prior denials and cumulative budget, and verify idle state before release.

Recheck nonsecret sync/publication metadata when the user reports disabling it; do not keep a resolved sync gate blocking authorized canonical writes. Plugin-enabled state alone is not proof of active publication. Keep existing private sync, public publication and configuration changes distinct when explaining a real authorization gate. Track memory persistence independently from wiki authoring, review and canonical application so a saved Honcho entry is not presented as completed wiki work. Report derived-page progress separately from staging raw evidence; archiving sources alone does not satisfy a documentation request.

Persist intent before one action and receipt afterward. Timeout, failed write, interrupted review or ambiguous result => uncertain: read exact targets before retry, compare before/after hashes and intended delta, inspect run/claim and partial effects. Require verified idle, source/packet freshness and remaining cumulative budget before at most one evidence-changing correction. Same blocker, actual denial, unknown ownership/effect or exhaustion => stop with owner/resume condition; never duplicate cards or rewrite files to see whether it worked. Stale/out-of-order Done cannot close a newer packet.

Worker returns task/run/action/packet identity, exact paths and before/after hashes, changed claims/coverage, citations, checks and real independent verdict if required, unresolved qualifications and remaining budget. Coordinator must read back exact paths and hashes, verify expected content, maintained convention checks and no out-of-scope writes, compare latest source/packet and required docs checklist, then reconcile both Wiki receipt and source outcome via its permitted interface with target readback. Only verified current coverage clears docs-required/pending. Missing/stale/ambiguous receipts remain pending, even when native task status is Done.

This is maintained instruction policy. Offline document tests establish discoverability and required clauses, not model decisions, atomic concurrency, native wake execution or autonomous closure. Report staged/installed/loaded/executed/assisted independently; live tests need separate bounded authorization and an independent reviewer.
