# Pi team CLI

Run `pi-team` instead of `pi` for the team workflow. It loads a deadline-protected copy of the bundled subagent example and the bundled todo example, and appends `workflow.md` to the parent prompt. Add `--model jev/auto` to use Jev for the coordinator; Pi subagent models and effort are pinned in role frontmatter. The AGY implementation worker is pinned separately to `gemini-4-hydrogen-high` at `high` effort.

Ask for an implementation to run the plan, implementation, tests, review, and fixes without routine approvals. Ask for a plan or review only to keep it read-only. In the TUI, `/todos` shows the current session branch's checklist. It is not a shared board, an unattended queue, or a crash-recovery scheduler.

Only the wrapper loads the team subagent and todo extensions. Delegated Pi children run without extension discovery or MCP; they retain their pinned models and built-in tools. The coordinator's extensions and MCP are unchanged. Each Pi subagent starts with a five-minute work window (override with a positive `PI_TEAM_SUBAGENT_TIMEOUT_MS`); the team writer starts with ten minutes. See deadline and fallback policy below. A Pi child has ten seconds to close after `agent_end`, followed by a five-second kill grace. Cleanup and cancellation never wait for Jev. A timeout is a failed delegation, not a completed review. The first failed Pi subagent call emits a UI error and blocks further Pi or AGY delegation in that agent run; the coordinator can still report the blocker and inspect evidence. A new user turn can retry after the cause is addressed. Pass an absolute `cwd` for the intended checkout; nonexistent or non-directory paths are rejected before launch. Known quota errors, CLI launch failures, and a child that exits without a final response are reported as failures rather than successful handoffs. Restart the coordinator to pick up launcher changes. An incompatible bundled subagent layout is rejected at launch rather than silently running without deadlines. `~/.pi/agent/extensions/agy-worker.ts` is auto-loaded in both plain Pi and `pi-team`; the wrapper enables team mode. Role files under `~/.pi/agent/agents` are inert without the subagent extension. The legacy Pi worker role is not used by the team workflow. Workflow rules are prompt policy, not sandbox or permission enforcement.

## Live AGY progress (plain Pi and Pi Team)

The existing `agy_worker` tool row updates while AGY runs. For example: `AGY · 2m 14s elapsed · 3 tool steps finished (last: read_file) · no new step events for 12s`. AGY 1.5.17's `--output-format stream-json` reports tool and model steps. Known tool names are shown; other names display as “tool”. Updates are coalesced to at most one per second. During silence the elapsed time refreshes about every ten seconds. Silence means no new observed step—not proof that the worker has stalled.

Partial updates omit prompts, paths, arguments, deltas, tool results and stderr. The final assistant report is unchanged; non-interactive permission denials stop the tool with summarized category/scope diagnostics without raw payloads, paths, display names, or stderr (see Roles below). The restricted Pi writer fallback does not use AGY's protocol.

## Deadlines and fallback routes

At a work deadline the parent asks the configured `typesafe/jev-latest` classifier about the current window. It receives only counts of model output and completed tools (Pi subagent or AGY), changes in worktree metadata (writer), window length and time since the last observation; no prompts, paths, diffs or stderr. The writer samples up to 128 modified/untracked non-ignored files every 30 seconds. Quiet reads, thinking without streamed events, and edits outside that sample may not be visible. Claim heartbeats and UI refreshes do not count as progress.

Activity within the last 90 seconds (or the window if shorter) and probability ≥0.70 earn another window, up to two extensions. With fresh evidence, an uncertain answer (>0.30), missing classifier or four-second decision timeout can earn one first extension. Otherwise stop and report why. A working TypeSafe credential in Pi is needed for Jev, not a chat model named `jev/auto`. Plain Pi's AGY timeout is unchanged.

The approved backup routes, in order, are `openai-codex/gpt-6.1-sol` and `opencode-go/deepseek-v4.1-flash`; selection requires a configured route on another provider. Recognized quota, region, authentication, model availability and service errors produce a warning in the UI (stderr without UI). Read-only user roles retry once with the same assignment, tools and requested effort. At final provider failure the coordinator switches its session model and continues with the existing context; a provider is not revisited in the same prompt. These providers can therefore receive the assignment or coordinator history. Ordinary task failures are not routing signals.

After AGY CLI or route failure, the worker **does not replay writes**. Inspect partial edits (including new files), check the claim and active writer, then resume on user direction with `resumeWithFallback: true` for the same worktree, issue and actor in this session. This starts the offered managed Pi model with read/search/edit/write only, no shell, MCP or extensions, inside the same lock, bubblewrap and heartbeat checks. This route requires bubblewrap `--tmp-overlay`: Pi can take credential/config locks in a private copy-on-write mount without making its host config writable. Refresh an expired login outside the worker. Exhausted routes, busy locks, tool denials and lost claims stop the stage. A failed primary Pi CLI cannot repair itself by changing provider.

## Interactive team and local run ledger

The separate `~/.pi/agent/bin/pi-team-run` command records durable checkpoints and polls CI. See the [pipeline runbook](pipeline.md) for installation, resume, the read-only watcher, and the separate opt-in Forgejo pilot runner for scoped merges.

Repository implementation tasks need a Beads issue and an authorized claim. Beads owns task state; `/todos` only reflects the current session. Follow the repo's existing sync procedure and don't close an issue until its definition of done is verified. Tracker changes and remote publication still require authorization.

Both launch modes preflight worktree writes and use a per-worktree advisory `flock` plus a Linux bubblewrap namespace. AGY sees a read-only host filesystem with its workspace bound writable; the PID namespace cleans up subprocesses when the launcher exits. The lock covers AGY invocations using this extension, not manual writers. The worker can still read user-accessible files and use the network; this is not a confidentiality boundary or a Codex-style escalation prompt. The Pi coordinator's own tools are unchanged. Authenticate AGY outside the worker if its login requires writing configuration. AGY stays in `accept-edits` with no approval bypass. Do not run this as an unattended service. See the [unattended factory plan](factory-plan.md) for the implementation and pilot gates. Honcho is recall-only by default; see the [operator opt-in](../honcho-cli/README.md) for verified publishing from the coordinator. No automated wiki update is configured.

## Roles

| Role | Provider/model | Effort |
| --- | --- | --- |
| Scout | `opencode-go/deepseek-v4.1-flash` | Low |
| Planner (routine / complex) | `openai-codex/gpt-6.1-sol` | Low / Medium |
| Worker | AGY `gemini-4-hydrogen-high` | High |
| Reviewer (localized / high-risk) | `openai-codex/gpt-6.1-sol` | Low / High |

The parent coordinates; the scout, planner, and reviewer use read-only tools. The coordinator gives the AGY worker an isolated task worktree and verifies its changes and checks. AGY print mode (`--mode accept-edits --print`) stays non-interactive without broadening permissions or adding approval bypasses: in live AGY 1.5.17, an explicit Ask rule can still return exit `0` / `SUCCESS` with a `denied_actions` entry containing only `action` (such as `read_file`) and `display_name`, omitting target paths and denial reasons. `agy_worker` stops on any `denied_actions` entry (even on `SUCCESS`), ignores `display_name`, stderr, freeform `reason` text, and raw payloads, and reports bounded deduplicated descriptors with count, category, allowlisted canonical action names (`unknown` otherwise), optional `path`/`target` scope, and recognized exact values on machine-readable `decision` or `reason_code` fields. Scope classification is conservative: omitted `path`/`target` reports `target scope unavailable`, lexically outside paths report `outside worktree path` on the nominal path with no host I/O, only checked existing in-worktree targets reached without traversing symlinks report `existing in-worktree regular file` or `other existing in-worktree path`, and any `..` component, symlink, home-relative (`~`), URL, glob, control character, missing path, error, timeout, or probe/depth cap reports `target scope unknown`. This intentional conservatism keeps the tool from guessing underlying rules, walking outside ancestors, or misclassifying scope, and ensures no raw paths or CLI output leak. To recover, inspect partial edits, have the coordinator handle broad discovery and shell checks, and send tightly scoped assignments naming exact worktree-relative paths rather than probing outside or protected data. Restart the coordinator after integrating `agy-worker.ts` changes so the updated extension loads. In team mode it renews the coordinator's existing Beads claim every 30 seconds during delegation, aborting AGY on a failed heartbeat. The Beads lease TTL must comfortably exceed the renewal interval plus the five-second heartbeat timeout. This is node-local, and idle, planning, review and CI waits are not renewed. Implementation authorization covers ordinary coding, tests, and review fixes, not commits, pushes, merges, deploys, or tracker changes.

## Frontend verification

For user-visible web changes, the coordinator checks the affected app in the task worktree. It runs relevant repo Playwright tests when locally runnable, or uses an available local Playwright browser to smoke-test the changed flow if there is no relevant test. For visual changes it inspects the rendered UI, not just the test exit status. The coordinator passes candidate-specific evidence to the read-only reviewer and reports any checks it could not run. This is a [workflow checkpoint](workflow.md#frontend-browser-checkpoint), not a launcher hook or a Playwright installer.

## Install and verify

Deploy with `python3 install-agents.py --tools pi --check` and then the same command without `--check`. Requires Linux with working bubblewrap PID namespaces and util-linux `flock`, a managed Pi release with both bundled examples and authenticated routes for the Pi role models, plus an authenticated `agy` on PATH with access to `gemini-4-hydrogen-high`. Repository implementation also needs a working `bd` CLI, an initialized repo tracker, and a documented sync procedure. Verify the tracker with `bd where --json` and inspect the selected issue before admitting work.

On 2026-11-21, before switching the worker to AGY, Pi 1.6.0 completed a live smoke test for the original four Pi roles. A separate disposable-repository test used GPT-6.2 Sol as coordinator: it updated code and docs in a task worktree, ran independent review, closed all milestones, and left the original checkout unchanged without a second user turn. RPC command discovery showed `todos` in `pi-team` but not plain `pi`. Model listing confirmed `jev/auto` was available; the end-to-end test did not exercise Jev routing.

## Proposed: Jev-assisted review routing

Not implemented. `jev/auto` currently selects the coordinator's model, not workflow stages. A future CLI-only integration would ask narrow probability questions about review-relevant properties, such as changes to access control, persisted data, and caller-visible behavior. Coordinator code would map those signals to suggestions for deeper review or extra tests. Start in shadow mode with sanitized fixtures; do not send raw private diffs or transcripts by default. Missing or uncertain signals keep the normal path. Deterministic checks, required review, and authorization stay in force.
